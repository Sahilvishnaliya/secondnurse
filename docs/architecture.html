Architecture

SecondNurse is deliberately small: a static front end, a thin Flask layer, and pure-Python core modules. Every AI call sits behind an env-gated adapter, and every fallback that could invent a result has been removed.

The SAM wire format, as parsed

SAM 3.1 answers in a special-token grammar on the Responses output_text lane — one line per frame:

<0f>0<|box;x1=353;y1=382;x2=453;y2=427;w=537;h=561|><|mask;x=0;y=0;data=46,101,~…|>
  • <Nf> opens frame N; indices can skip and need not be ascending.
  • Each record is an object id, one box token, one mask token. Box coordinates are source pixels; w/h repeat the frame size.
  • Mask payloads are base85, ~ lossless or ! one-bit. SecondNurse requests one_bit for payload size, then decodes with the official meta_sam_parser.
  • Mask rasters are box-cropped; overlap is computed by placing each raster at its box origin in frame coordinates — true pixel intersection, with box overlap only as a fallback if a payload fails to decode.

Why per-prompt requests

SAM accepts exactly one concept per request; list syntax returns nothing. Four prompts therefore cost four requests per frame. This is the dominant latency and cost term, and the reason watch mode samples at ~3s instead of pretending to be a video-rate system.

Security posture

  • API keys exist only as server-side environment variables.
  • Request bodies are capped (8 MB — one camera frame), JSON shapes validated, compile and live-segment routes rate-limited per client.
  • Responses carry CSP, nosniff, frame-deny, referrer, and permissions headers.
  • All user-supplied text renders via textContent; there is no HTML injection path from protocol text or SAM labels.
  • Frames are forwarded to the Meta API and not stored; no analytics, no third-party calls from the browser except fonts.

Deployment

One codebase, two hosts: Flask serves everything locally; on Vercel, static files serve directly and api/index.py runs the same Flask app as a serverless function, with a rewrite that passes the original route through. Environment variables are identical in both.

Design system

The product surface follows DESIGN.md in the repo root — a token spec (warm parchment, Fraunces 500, clinical teal, WCAG-measured text colours, 8px grid, 48px targets) that lints clean with the @google/design.md CLI. These docs use a separate, quieter GitBook-style system: monochrome, flat, content-first.
