IoT Devices

SecondNurse is software, but it watches a physical bench. This page is the hardware story: what the camera sees with, what the bench can sense, and how alerts leave the screen and enter the room.

Status labels are honest: Works today (implemented in this codebase), Adapter-ready (the API surface exists; a small integration wires it), Roadmap (designed, not built).

How devices connect

Today: one HTTPS path

The browser is the gateway. Camera frames go to POST /api/segment-live; events render in the session. Any device that can POST a JPEG frame or a JSON event to the SecondNurse server can join — that is the entire integration contract.

Adapter-ready: events in, alerts out

  • Sensor events in: a small bridge (Pi/ESP32) POSTs JSON events — cap opened, clamp state, scale reading — which the session log records alongside vision events with a shared timestamp.
  • Alerts out: breach events are emitted to a configurable webhook; home-automation platforms (Home Assistant, Hue, smart speakers) subscribe there. Home Assistant over MQTT or HTTP is the reference target.
  • Time is the join key. Every device event carries an epoch timestamp; the session record aligns vision, sensor, and alert streams on it.

Device data & privacy

  • Camera frames are sent only to the configured Meta API for segmentation; SecondNurse stores no video.
  • Sensor events are numbers and timestamps (cap opened, clamp closed) — no content, no audio, no continuous recording.
  • Devices pair to a session locally; there is no always-on cloud listener in the home.
  • A physical camera shutter / hardware mute remains the patient's — the system must be visibly off when it is off.
