FAQ & Troubleshooting

General

Is SecondNurse a medical device?

No. It is an educational training system for sterile technique, used with a training kit. See Safety & Scope.

Does SecondNurse run in real mode?

Yes — real mode is the only mode. Camera frames go to live SAM 3.1 and protocols compile with live Muse Wonder. Without a Meta API key the AI endpoints return 503, because no result is ever invented.

Which procedures does it support?

Any procedure you can (a) write as steps and (b) perform with visually distinct parts: peritoneal dialysis exchanges, home infusion connections, catheter care, wound dressing. The compiler turns the text into checks; SAM prompts name the parts.

Setup problems

Header says “key required”

MODEL_API_KEY or SECONDNURSE_MODE=live is missing where the server runs. On Vercel, set both for Production and redeploy; locally, check your .env is loaded by the process you started.

Camera will not start

The page must be on HTTPS or localhost, and permission must be granted for this origin. In the docs and app, camera code only runs after you press Enable camera — nothing records passively.

Compile returns 503

Same configuration gate as above. Compilation is a Muse Wonder call; there is intentionally no offline substitute producing official-looking graphs.

Detection problems

SAM finds nothing (“not found”)

  • Reframe: the object may be out of shot, occluded, or too small. Move the camera closer / higher.
  • Light: add even light; kill backlight and specular glare on plastic.
  • Prompt: keep it a short noun phrase with a concrete attribute — red connector, not the thing I connect.
  • Kit: confirm colours match the prompts (red tip, blue cap). Prompt and kit are a pair.

Boxes jump between objects

Two similar objects in frame will compete for one prompt. Separate them spatially, differentiate colour, and keep the bench uncluttered — the sterile field should contain only the procedure.

A real touch did not alert

Check, in order: was the overlap ≥40px² in the analyzed frames (see Live Results)? Did it persist across two consecutive analyzed frames? Was the tip found in those frames at all? Slow the movement during early sessions; the cadence is ~3s per frame.

False alerts on clean runs

Usually a hand passing over the tip in 2D while above it in 3D. Raise the camera (more top-down = less parallax), tighten the bench, and confirm the threshold in Live Results before changing it — thresholds are clinical-training decisions, not vibes.

Performance

Latency is several seconds

Expected: one SAM request per prompt per frame. Reduce prompts, reduce frame size, or move to an edge node (IoT Devices) that only sends frames on motion.

Rate limited (429)

Compile allows 30/min and live segmentation 20/min per client. Live watch at 3s/frame with default prompts sits inside the limit; parallel tabs may not.

Still stuck?

Read the failing frame, not the code: open Live Results, note which prompt returned “not found”, and fix the physical setup for that object first. In this system, most software symptoms are bench symptoms.
