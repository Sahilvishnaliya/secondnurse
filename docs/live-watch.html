Live Watch

Live Watch is the core loop: your camera, SAM 3.1 masks, a deterministic rule engine, and an alert that arrives before a contaminated connection is made.

The frame pipeline

  1. The browser captures a frame (max 640px wide, JPEG) from the camera every 3 seconds in watch mode, or on demand.
  2. The server sends one SAM 3.1 Responses request per concept prompt — SAM accepts a single noun phrase per request.
  3. Responses stream back in Meta's special-token wire format. SecondNurse parses boxes and masks per object, per frame.
  4. Masks are decoded with the official meta_sam_parser; hand∩tip overlap is measured in pixels.
  5. Rules evaluate the frame; consecutive-frame logic confirms or clears the event.

Prompts used

sterile field matfieldDefines the containment boundary for the FIELD rule.

Prompts are short noun phrases on purpose: commands and questions (“segment the…”, “where is…”) are unreliable with SAM. Negation and spatial phrasing are avoided; position logic lives in the rule engine, not the prompt.

The three rules

TOUCH — contamination

Hand mask ∩ sterile-tip mask ≥ 40px² on two consecutive analyzed frames. Two frames, because one noisy frame must never stop a procedure — and because in live mode frames arrive every ~3 seconds, consecutive confirmation is the temporal evidence available.

FIELD — sterile boundary

The cap's centroid must remain inside the sterile-field mask while it is a free object. A cap set down outside the field is flagged; the patient discards it and takes a fresh one.

ORDER — protocol sequence

Steps must complete in the compiled order. The server-side trace evaluator (POST /api/evaluate) flags a jump to step n+2 before step n+1 completed.

Reading the console

  • hand ∩ sterile tip: the current frame's measured overlap in px², with the method used (mask or box fallback).
  • Consecutive overlaps: the confirmation counter toward a TOUCH alert.
  • Cap in sterile field: yes / NO / — (not enough objects found).
  • Last frame latency: full round trip for all prompts on the last frame.
  • Compliance score: starts at 100; −25 per confirmed breach. A session record, not a clinical judgement.
  • Event log: every camera, compile, analysis, and breach event with session time.

Latency, honestly

Each frame costs one SAM request per prompt (four by default), plus mask decoding. Expect an analyzed frame every few seconds, not a 30fps overlay. That cadence catches “stop before you connect” events — the clinical moment that matters — and is not a mid-motion interception system. The UI always labels the last latency so the operator can see the real number.

When objects are not found

A prompt can legitimately return zero matches (occluded tip, hand out of frame). The console shows “not found” in Live Results rather than guessing. Rules simply do not evaluate what was not seen, and the overlap counter resets only on a measured non-overlap, not on a missing frame.
